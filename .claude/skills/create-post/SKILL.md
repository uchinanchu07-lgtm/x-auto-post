# X投稿作成スキル

ユーザーの X 投稿を一緒に作るためのスキル。

## ワークフロー

### Step 1: トレンド調査 + ネタ提案

スキル発動したら、まず以下を行う:

1. Web検索で今日のトレンド・話題を調べる（2〜3回検索）
   - 「X Twitter Japan trending today」
   - 「AI ニュース 最新」
   - ユーザーの領域に関連するキーワード
2. `profile/profile.json` を読み、ユーザーの価値観・ポジショニングを把握する
3. トレンドとプロファイルを掛け合わせて、**投稿ネタを3つ提案**する

提案フォーマット:
```
今日のトレンドを調べました。

① [トレンド/話題] × [ユーザーの経験・視点]
   → こういう切り口で投稿すると刺さりそう

② [トレンド/話題] × [ユーザーの経験・視点]
   → こういう切り口で投稿すると刺さりそう

③ [トレンド/話題] × [ユーザーの経験・視点]
   → こういう切り口で投稿すると刺さりそう

どれが気になりますか？別のネタがあればそれでもOKです。
```

### Step 2: ユーザーの話を聞く

ユーザーがネタを選んだら（または自分のネタを出したら）:

- 「それについてどう思いますか？」
- 「何か具体的なエピソードや数字はありますか？」
- 「誰に向けて言いたいですか？」

**聞きすぎない**。1〜2回のやり取りで十分。ユーザーが話したことをそのまま活かす。

### Step 3: 投稿文を仕上げる

ユーザーの話を元に、投稿文を **2案** 作る。
280文字で語りきれないネタは **スレッド（2〜4ツイート）** も提案してよい。

#### 品質基準
- 単体投稿: 280文字以内
- スレッド: 各ツイート280文字以内、1ツイート目だけで成立するフックがあること
- 最初の1文で手を止めさせるフックがあるか
- ユーザー本人の経験・言葉が入っているか
- 今のトレンドに乗っているか（該当する場合）
- AIっぽくないか（定型的な言い回しを避ける）

#### スレッドの書き方
スレッドの価値は「各ツイートが140文字ギリギリまで使って中身が分厚い」こと。
短い文を分けただけのスレッドは意味がない。

- 各ツイートを `---` で区切る
- **各ツイートは120〜140文字を目安に、情報量を詰める**
- 1ツイート目: フック（これだけでもRTされる強さ、140文字ギリギリ）
- 2ツイート目以降: 具体例、数字、体験談をたっぷり書く。スカスカ禁止
- 最後: まとめ or CTA
- スレッドにするなら3〜5ツイート。2ツイートだけのスレッドは中途半端

#### 参考: 伸びる投稿のパターン
- **問題提起 + 具体的数字**: 業界の常識に疑問を投げかけ、自分の実績で裏付ける
- **対比構造**: ビフォー↓アフター、のような箇条書き対比
- **短文のキレ**: 一言で刺さる短文（10〜20文字）
- **率直な数字**: 売上、期間、コストなど具体的な数字を隠さず出す

#### 絶対やらないこと
- profile.json の ng_expressions に含まれる表現
- 感嘆符を3つ以上連続で使わない
- AIっぽい定型表現（「〜という観点で」「〜は重要です」等）
- プロファイルの実績を毎回入れる（必要なときだけ）
- 断定口調（「〜だ」「〜が必要」「〜て当然」「〜じゃない」で言い切る）→ メンタルが弱っている読者が傷つく可能性がある

#### 語尾の方針
断定を避け、寄り添う口調にする。
- NG: 「変えるべきは環境だ。」「叱っても意味がない。」
- OK: 「変えるべきは環境かもしれません。」「叱っても意味はないと思うんです。」
語尾の例: 「〜かもしれません」「〜と思います」「〜ではないでしょうか」「〜なんです」「〜ですよね」

### Step 4: スプシに書き込む

投稿文が確定したら、プロジェクトルートで `addPost` 関数を使ってスプシに書き込む。
ID採番・投稿予定日時・文字数は全て自動で入る。

```bash
node --input-type=module -e "
import { addPost } from './tools/lib/sheets.mjs';
const text = \`ここに確定した投稿文\`;
const { id, scheduledAt } = await addPost(text);
console.log('スプシに書き込み完了: ID ' + id + ' / 予定: ' + scheduledAt);
"
```

スレッドの場合は `---` 区切りで1つのセルに格納する。投稿時に自動でスレッド連投される。

```bash
node --input-type=module -e "
import { addPost } from './tools/lib/sheets.mjs';
const text = \`1ツイート目の内容
---
2ツイート目の内容
---
3ツイート目の内容\`;
const { id, scheduledAt } = await addPost(text);
console.log('スレッド書き込み完了: ID ' + id + ' / 予定: ' + scheduledAt);
"
```

書き込み後、ユーザーに割り当てられた予定日時を伝えて「スプシで確認してOKなら承認済みに変えてください」と案内する。

### Step 5（任意）: 投稿の実行

ユーザーから「投稿して」と言われたら:

```bash
node tools/post-to-x.mjs
```

全件投稿する場合:
```bash
node tools/post-to-x.mjs --all
```

### Step 6（任意）: パフォーマンス振り返り

ユーザーから「伸びた投稿は？」「振り返りして」と言われたら:

```bash
node tools/review-performance.mjs
```

投稿済みツイートのインプレッション・いいね・RT を X API で取得し、トップ投稿を分析して `profile.json` の `top_patterns` を自動更新する。

## 基本姿勢

- **提案ファースト**: 質問する前にまずネタを提案する
- **聞きすぎない**: 1〜2回のやり取りで投稿文に持っていく
- **ユーザーの言葉を活かす**: AIが勝手にきれいにまとめない。ユーザーが話した表現をそのまま使う
- **選択肢は少なく**: ネタ提案は3つ、投稿文は2案まで
